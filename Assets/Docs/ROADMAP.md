## 1. 目标与边界

| 项目 | 约定 |
| --- | --- |
| 核心目标 | 打磨现有微缩桌面 Demo 的画面与操作体验，不新增关卡；唯一计划新增的玩法是真实蘸墨与脚下自由盖印 |
| 画面方向 | 保留手绘文具、纸张和小人的质感；改善光影、主体层次，尝试三渲二材质与适量描边 |
| 体验方向 | 改善 3C（角色、控制、相机）、打点与跳下手感、任务反馈和 UI |
| 技术路线 | 先使用 Unity 2022.3 + URP 14；迁移 URP 不等于升级 Unity 6，本轮不升级引擎 |
| 实施方式 | 3C 与墨水暂时冻结，优先画面；保留场景布局、任务规则与资源；不同时升级引擎、更换输入框架或重做玩法 |
| 试作性能目标 | Windows PC；1920×1080 与 2560×1440，目标稳定 60 FPS；目标设备型号和实际 CPU/GPU 帧时间尚未测定 |
| 学习方式 | 在实际操作中解释渲染概念；每次讲清“改哪里、为什么、观察什么、如何恢复” |

暂定视觉方案：窗光作为桌面主光，暗部保留细节；尝试柔和的 2～3 段明暗；角色和关键物件轮廓更清晰，背景描边克制；纸、木、塑料、玻璃保留不同表现。**这些仍是试作方向，不是已确定的美术规范。**

### 光影试作顺序

1. 固定相机、分辨率和质量档位，保存当前截图；先确认角色、纸面与背景的视觉主次。
2. 确定窗光的方向与色温，再调环境光和暗部；阴影距离依据实际可见范围，不直接套最高预设。
3. 检查 Gamma/Linear 与数据贴图导入；若切色彩空间，单独提交和复核，不顺便改 Toon 与描边。
4. 在样例上比较 Toon 明暗层次，再加入描边；验证静态画面和实际移动，保留独立开关方便对照。
5. 最后调整反射、接触阴影、抗锯齿与适量后处理；不靠强 Bloom 或大面积黑边掩盖基础照明问题。

当前外壳覆盖主体，屏幕空间淡边补薄纸、开放网格与墙面；仅按几何信息找边，不按贴图笔画找边。透明纸独立处理，不写深度。全屏 Feature 按需要求深度与几何法线，全局 Depth / Opaque Texture 仍关闭；**输入声明也会增加预通道成本，必须测量，不等于免费。** 使用与限制见 SCENE_STYLE。

未来自定义 Shader 必须继续支持主贴图切换；明确主贴图属性及 `MainTexture` 标记/兼容接口，不让任务逻辑依赖某个专用 Toon 属性名。[主贴图接口说明](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Material-mainTexture.html)

**会涉及 Shader，但不是重写渲染管线。** URP 继续负责整体流程；Shader 定义表面怎样显示；Material 保存某个物件使用的参数。结合当前已有手写 `InkStamp.shader` 和逻辑工程背景，建议第一版使用小范围 ShaderLab / HLSL，参数暴露在 Inspector；Shader Graph 可用于理解和可视化原型，也可以通过 Custom Function 调用 HLSL，暂不同时维护两套 Toon 实现。

学习顺序：先理解“法线 + 光方向决定明暗”，再看如何把连续亮度分段，最后看顶点扩张 / 屏幕深度怎样形成轮廓。不要求先掌握完整图形学。相关版本资料：[Shader Graph 14 自定义函数](https://docs.unity3d.com/Packages/com.unity.shadergraph@14.0/manual/Custom-Function-Node.html)、[URP 14 全屏 Renderer Feature](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/manual/renderer-features/renderer-feature-full-screen-pass.html)。

## 6. 边做边学

| 到哪一步 | 需要理解的概念 | 对应练习 |
| --- | --- | --- |
| S0 | 渲染管线决定怎样绘制；URP Asset 管全局质量；Renderer 管具体渲染流程与扩展 | 在 Graphics、Quality 和 URP Asset 中确认实际使用的配置；理解旧预设为何先保留 |
| S2 | Shader 是绘制规则，Material 是参数；直接光、环境光、阴影与色彩空间共同影响结果 | 用同一物件逐项切换/调整，观察光、底图和材质参数分别改变什么 |
| S2/S5 | 实时与烘焙照明、反射探针服务不同需求 | 区分静态桌面与移动角色，检查旧烘焙数据，不默认迁移后仍完全等价 |
| S3 | 法线表示表面朝向；Toon 的明暗分段改变光照表现，不等于降低模型面数 | 比较 Lit 与 Toon 样例，调分段边界、暗部颜色，检查投影和任务贴图 |
| S4 | 外壳描边与屏幕空间描边的输入、覆盖范围和成本不同 | 同视角比较线宽、接缝、透明物件、运动稳定性；按效果和成本选路线 |
| S6 | 帧时间比单个 FPS 更适合比较；CPU、GPU、GC 与纹理内存是不同问题 | 在目标构建测量同一路径，找到主要开销后一次改一项 |

学习资料按当前版本阅读：[URP 14 安装与启用](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/manual/InstallURPIntoAProject.html)、[URP Asset 设置](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/manual/universalrp-asset.html)、[Unity 2022.3 Profiler](https://docs.unity3d.com/2022.3/Documentation/Manual/Profiler.html)。不用现在就掌握全部 Shader/HLSL，也不直接照搬 Unity 6 的渲染扩展示例。

## 7. 验收与修改规则

- 每批只处理一个主题：管线、色彩空间、照明、材质、描边、控制分别留恢复点；先记录修改前状态，再改参数。
- 所有资产移动保留 `.meta`/GUID；不随意改任务索引、帧顺序、消息、FBX 骨骼路径或玩家 Animator 挂载关系。
- 新资源沿用 [ASSETS.md](ASSETS.md) 的归属；Shader、Renderer Feature 按实际出现的职责放置，不提前搭空架构。
- 画面对比固定相机、任务阶段、分辨率、质量档位和灯光；保留原方案与试作方案截图，不只凭记忆判断。
- 动态检查覆盖停走、反向、书页/书脊、边缘、跳下、重叠触发区、四项任务、结尾以及重复进入场景。
- UI 检查至少覆盖 16:9、16:10、较窄窗口和较宽窗口；是否支持移动端待确认，不默认扩展平台。
- 性能以目标设备上的构建为准，区分编辑器与构建、VSync/帧率上限；记录 CPU/GPU 帧时间、GC、纹理内存和加载时间。URP/Toon 不自动意味着更快。[Profiler 说明](https://docs.unity3d.com/2022.3/Documentation/Manual/Profiler.html)
- 旧预设、备份和测试资源先查依赖，之后单独清理；当前不引入 DOTS、Addressables 或全面架构改造。
